## Механика отправки

1. Отправитель: hello@ccapital.pro (Яндекс 360; SPF/DKIM у домена настроены, проверено).
   Нужен пароль приложения Яндекс ID → передать и запускать send.py.
2. Прогрев: дни 1–3 по 15–30 писем (сегмент A), дальше 30–50/день (B, затем C).
   Порядок: A (204) → B (962) → C_kld (2 411). Вся база ~2,5 месяца при 50/день.
   Массовый залп запрещён: лимит Яндекса ~500/день, риск блока ящика.
   **Инцидент 06.07:** после 7 писем антиспам Яндекса дал 554 «suspicion of SPAM»
   (до этого рвал соединение после каждого письма — ранний признак). Вывод: паузы
   45–90 с слишком агрессивны для непрогретого ящика. Новый темп: пауза 3–7 мин
   (`--pause 180-420`, теперь дефолт), максимум 10–15 писем в день первую неделю.
   При 554 скрипт останавливается сам; повторный запуск — не раньше чем через
   несколько часов.
3. send.py: журнал sent.csv (без повторов), unsubscribed.txt, пауза 45–90 с,
   автостоп при SMTP-лимите, --dry-run для проверки.
4. Замер: UTM utm_source=email, utm_campaign=ved|private|kld → Метрика; главный KPI — ответы.
5. Ответившим — созвон/NDA-разбор; отписавшихся — в unsubscribed.txt немедленно.
